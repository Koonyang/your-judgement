# 1화 수직 슬라이스 설계

> 상태: 사용자 승인됨, 구현 완료 (2026-11-20 최종 리뷰 수정 반영)

> 2026-11-19 작성. 게임 규칙의 원본은 `docs/design/gameplay.md`이고, 이 문서는 1화를 처음부터 끝까지 플레이 가능하게 만드는 범위와 구조를 정한다.

## 1. 의도
- 첫 구현 목표. 1화(편의점 소액 절도, 튜토리얼)를 **공판 전 → 선고 → 항소 판정 → 판결 기록실**까지 한 번에 플레이할 수 있게 만든다
- 목적은 두 가지다
  1. "실제 법정의 리듬"(짧은 기일, 서면 중심, 기록 검토)이 게임으로 느껴지는지 확인한다
  2. 시나리오 데이터 구조와 판정 로직이 전 단계에 걸쳐 맞물리는지 검증한다. 2화 이후는 데이터만 추가해서 만들 수 있어야 한다

## 2. 목표 / 비목표 / 반목표
**목표**
- 전 단계를 얇게 관통(사용자 결정: A안 "전체 흐름 얇게")
- 판정 로직(쟁점 보드 → 유무죄, 양형 계산, 집행유예 권고, 항소 발생, 항소심 판정)은 화면과 분리된 순수 TypeScript로 만들고 테스트로 검증한다
- 시나리오는 JSON 데이터 파일 하나로 1화 전체를 기술한다

**비목표 (이번에 안 만듦)**
- 이탈 사유 슬롯, 선입견 사건 판정(편향/선을 넘음), 보충신문의 입증 대행·선입견 질문: 3화부터 쓰는 장치. 단, **판정 로직 모듈에는 구현**해서 테스트로 검증하고 UI만 1화에서 숨긴다(이탈 슬롯 판정은 2화 이후 데이터에 바로 필요하기 때문)
- 합의부·배석판사, 막간 뉴스, 엔딩, 세이브 슬롯
- 실제 도트 아트, 사운드(효과음 자리만 둠)
- 모바일 레이아웃 최적화(데스크톱 브라우저 1280×720 기준)

**반목표 (기술적으로 돌아가도 실패인 것)**
- 역전재판식 연출(구두 언쟁, 모순 지적 버튼)이 끼어드는 것
- 판정 로직이 장면 코드 안에 흩어져 시나리오 추가 때 코드를 고쳐야 하는 것
- 플레이어가 판사보다 많은 정보를 보는 것(1화는 예외 없음)

## 3. 제약
- 스택: TypeScript + Phaser 3 + Vite, 웹 브라우저 (CLAUDE.md 확정)
- 고증 최우선. 절차 문구와 양형 수치는 원문 확인값을 쓰고, 미확인은 데이터에 `todo_verify` 표시
- 문서·UI 텍스트는 한국어

## 4. 접근 방식 (검토한 것)
| 안 | 내용 | 판단 |
|---|---|---|
| **A. Phaser 장면 + HTML 문서 UI 오버레이** | 법정 장면·인물·대사창·연출은 Phaser, 기록 열람·쟁점 보드·양형·판결서는 캔버스 위 HTML/CSS 패널. 판정 로직은 순수 TS | **채택** (사용자 결정). 한글 장문·스크롤·형광펜·드래그 슬롯을 브라우저 기능으로 해결 |
| B. 전부 Phaser | 화면 일관성 좋음 | 한글 비트맵 폰트·스크롤·텍스트 선택·입력창을 직접 구현해야 해서 분량이 몇 배 |
| C. HTML 위주, Phaser는 연출만 | 개발 가장 빠름 | 확정 스택을 사실상 버림 |

## 5. 구조

### 5.1 레이어
```
data/scenarios/ep01.json        시나리오 데이터 (코드와 분리)
src/engine/                     순수 TS, Phaser·DOM 의존 없음. Vitest로 테스트
  scenario/   스키마(타입 + 런타임 검증), 로더
  flow/       진행 상태 머신 (단계·기일·이벤트)
  board/      쟁점 보드: 칸, 증거 연결, 판정 → 유무죄
  sentencing/ 양형: 특별인자 → 권고영역·범위(특별 조정 포함), 일반인자, 집행유예 권고, 여유폭
  judgment/   판결서 조립 (주문·범죄사실·증거의 요지·법령의 적용·양형의 이유)
  appeal/     항소 발생, 항소심 판정, 불이익변경금지
  record/     판결 기록실 항목 생성
src/ui/                         HTML 패널 (기록 열람, 쟁점 보드, 양형, 판결서, 기록실)
src/scenes/                     Phaser 장면 (법정, 선고 연출)
src/game/                       엔진 상태 ↔ 장면·패널 연결 (이벤트 버스)
```
- 엔진은 **입력(시나리오 + 플레이어 선택) → 출력(상태·판정 결과)** 의 순수 함수 위주로 만든다. 화면은 엔진 상태를 그리기만 한다
- 진행 상태는 단일 객체(`GameState`)로 두고, 플레이어 행동은 액션으로 엔진에 전달한다

### 5.2 화면 흐름 (1화)
| # | 단계 | 화면 | 플레이어 조작 |
|---|---|---|---|
| 0 | 사건 배당 | 사건 대기열(기록 더미) | 사건 열기 |
| 1 | 공판 전 | 기록 패널: 공소장, 피고인 의견서만 | 읽기, 형광펜 |
| 2 | 모두절차 | 법정 장면, 자동 진행. 참여관 안내(1화 한정) | 진행 버튼. 끝에 쟁점 보드 자동 생성 → 확인 |
| 3 | 증거 채부 | 법정 + 증거목록 패널 | 진행 버튼. 동의 증거 편철·해금, 부동의 조서는 표목만 잠김 |
| 4 | 증인신문 (점주 1명) | 법정 대사 흐름 | 상시 **제지**, **이의 결정**(인용/기각), 보충신문(명확화 질문만, 안 묻기 가능) |
| 5 | 피고인신문 | 법정 대사 흐름. 검사 → 변호인 → 재판장 | 제지, 이의 결정, 보충신문 (증인신문 장치 재사용) |
| 6 | 결심 | 자동: 구형 → 최종변론 → 최후진술 → 종결 → 선고기일 지정 | 진행 버튼, 최후진술 형광펜 |
| 7 | 선고기일 전 재검토 | 기록 패널 전체 | 자유 열람 |
| 8 | ① 유무죄 | 쟁점 보드 | 칸마다 증거 연결, 증명됨/의심 남음 |
| 9 | ② 양형 | 양형 패널: 유형 선택, 특별·일반인자 체크, 권고범위·구형 선 표시, 집유 참작사유 체크, 형량 입력 | 입력 |
| 10 | ③ 판결서 | 판결서 패널: 증거의 요지·양형의 이유 슬롯, [추가로] 자유 문구 | 카드 끼우기, 선택 입력 |
| 11 | ④ 선고 | 주문 3박자 → 도장 "탁" → 내면의 법봉 3타 | 진행 |
| 12 | 항소 | 결과 화면: 항소 여부(검사·피고인) → 항소심 판정(기각/파기자판, 지적 사항) | 읽기 |
| 13 | 판결 기록실 | 사건 1건 기록 | 읽기 |

- 1화는 판결서 단계에서 **권고범위 밖 형량 입력을 막지 않는다**. 대신 여유폭 밖이면 참여관이 "양형기준을 벗어나면 이유를 적어야 한다"고만 안내하고, 이탈 슬롯 없이 그대로 항소 판정으로 간다(근거 무게 0 → 검사·피고인 항소 시 파기). 3화부터 이탈 슬롯이 열린다 `[내 판단, 검토 바람]`

### 5.3 판정 로직 명세 (엔진)
`docs/design/gameplay.md` 평가 섹션을 그대로 구현한다. 요점만 옮긴다.
- **유무죄**: 모든 칸 증명됨 → 유죄. 한 칸이라도 의심 남음 → 무죄. 증거 0장인 칸을 증명됨 → 사실오인 플래그
- **보강법칙**: **보드 전체 단위**로 판정한다. 보드 어디에도 자백 외 증거가 연결되지 않았으면 위반. 보강증거는 범죄사실 전부가 아니라 자백의 진실성을 담보할 정도면 된다는 판례 취지를 따른다 `[판례번호 확인필요]`
- **무죄 쪽 오류 (사용자 결정 A)**: 회차 데이터에 칸별 **항소심 판단**(증명됨/의심 남음 + 근거 증거)을 둔다. 플레이어가 "의심 남음"으로 둔 칸을 항소심이 "증명됨"으로 보면 사실오인으로 파기, 유죄 자판. 판단이 갈리는 칸(4·5화)은 데이터에서 "항소심도 의심 남음"으로 두어 무죄가 유지된다. 항소심 판단은 태도 변화 플래그(아래)에 따라 달라질 수 있다
- **권고영역**: 특별인자 평가(행위인자 우월, 같은 성격끼리 개수 상쇄, 처벌불원은 절도에서 행위인자와 동등) → 감경/기본/가중. 특별 조정(같은 방향 2개 이상 등) 적용
- **집행유예 권고**: 주요사유 개수 규칙 + 일반사유 역전 규칙 → 집유 권고/실형 권고/종합 판단
- **여유폭**: [추가로] 작성 시 권고범위 경계값 ±20%, 미작성 시 0
- **항소 발생**: 확률 없이 확정 규칙. 검사 = 무죄 또는 선고형 < 구형 × 1/2(집유도 형량으로만 비교 `[내 판단]`). 피고인 = 회차 데이터의 규칙(1화: 실형이면 항소, 집유면 안 함)
- **파기자판 형량**: 항소심이 다시 평가한 권고범위 안에서 원심 형에 가장 가까운 경계값. 절차 위반으로 파기되면 그 위반으로 잃은 카드를 복원한 뒤 다시 계산한다. 그 결과에 불이익변경금지를 적용한다 `[내 판단]`
- **항소 없이 확정 (사용자 결정 B)**: 앞 단계 위반은 원칙적으로 묻힌다. **1화만** 결과 화면에서 참여관이 "항소가 있었다면 이런 지적을 받았을 수 있다"고 한 줄 짚는다. 2화부터는 묻힌다
- **항소심**: 직권(법리·사실오인·영향 있는 절차 위반) → 양형부당(이탈 폭 vs 근거 무게) → 불이익변경금지 → 결과 종류
  - 결정(R7): 법리·사실오인으로 파기하면 유무죄는 항소심 판단(`appealView` 중 `when` 충족분)을 따른다. 전부 증명됨 → 유죄, 형은 항소심 권고범위로 조정. 하나라도 의심 남음 → 무죄 자판 (형소법 §310 취지에 가깝게)
  - 결정(R9): 절차 위반으로 잃은 카드를 복원할 때, 실제로 들은 진술(`heard`)이 철회한 카드(예: 처벌불원 철회)는 위반이 없었어도 남지 않았으므로 복원하지 않는다
  - 결정(R11): 이중평가 감쇠(특별인자 무게 × 0.5) 대상은 플레이어 체크가 아니라 기록상 권고영역을 정한 특별인자 전부(복원 후 보유 카드 기준)다
- 모든 수치(여유폭 비율, 검사 항소 비율, 카드 무게)는 설정 파일 또는 시나리오 데이터에서 읽는다

## 6. 1화 사건 초안 (시나리오 데이터의 내용)
> 내용 초안이다. 인물 이름·대사는 구현 중 데이터로 작성하고 따로 검토받는다.

- **공소사실**: 피고인(60대, 일용직)이 편의점에서 도시락·우유 등 합계 1만 2천 원 상당을 계산하지 않고 가지고 나가 절취. 형법 §329 `[법정형 원문 확인필요]`
- **피고인 의견**: 공소사실 전부 인정(자백 사건) → 보강법칙 튜토리얼 겸함. 의견서에 생활고 사정이 적혀 있다(생계형 카드 출처)
- **쟁점 보드 칸**(자동 생성, 전부 "다툼 없음"): 타인의 재물 / 절취(점유 이전) / 고의 / 불법영득의사
- **증거목록**
  | 증거 | 제출 | 변호인 의견 | 상태 |
  |---|---|---|---|
  | 피고인 피의자신문조서 | 검사 | 동의 | 편철 (자백) |
  | 편의점 CCTV 영상 캡처 | 검사 | 동의 | 편철 (보강증거) |
  | 피해품 목록·영수증 | 검사 | 동의 | 편철 |
  | 점주 진술조서 | 검사 | **부동의** | 표목만 잠김 → 점주 증인 채택 |
  | 수사보고(전과 조회) | 검사 | 동의 | 편철 (동종 전과: 최근 5년 내 벌금 3회) |
  | 처벌불원서(점주) | 변호인 | 검사 동의 | 편철 (처벌불원·피해 회복 카드) |
- **태도 변화 이벤트** (사용자 제안, 아래 7절 스키마). 법리는 그대로이고 플레이어 행동에 따라 양형인자가 생기거나 사라져 정답 범위가 바뀐다. 플레이어 선택에만 따르며 무작위는 없다(사용자 결정). 1화에는 "끊어야 할 대목"과 "끊으면 안 되는 대목"을 같이 넣어 무조건 제지/방치가 정답이 되지 않게 한다
- **증인신문 (점주)**
  - 주신문(검사): 범행 경위 확인. 검사가 "전에도 여러 번 없어진 물건이 있었죠?"처럼 **기소 안 된 여죄** 쪽으로 묻는다 → 변호인 **이의**(공소사실과 무관) → 올바른 결정: 인용
  - 반대신문(변호인), 두 대목이 섞여 있다
    - **정당한 대목**: 피고인이 찾아와 사과하고 물건값을 갚았는지 묻는다(말투가 다소 거슬림). 끊으면 처벌불원서의 진정성을 뒷받침하는 답변이 사라져 **처벌불원 카드가 무게를 잃는다**(카드 상실). 정당한 신문 제지로 지적(판결 영향 on)
    - **모욕적 대목**: "사장님도 관리를 소홀히 한 것 아니냐"(위압적·모욕적 신문 금지 `[형소규칙 §74, 확인필요]`). **제지하면** 처벌불원 유지. **방치하면** 점주가 긁혀서 "사실 마지못해 써준 거다, 처벌을 원한다"며 **처벌불원 철회** → 처벌불원 카드 소멸, "피해 회복"만 남음(일반인자 '상당한 피해 회복'으로 격하) `[내 판단: 철회 시 변제 사실은 남으므로]`
  - 증언 후 점주 진술조서 해금(§312 계열 `[확인필요]`)
  - 보충신문: 명확화 질문 2개(가져간 물건의 용도, 피해 회복 시점). 안 물어도 됨
- **피고인신문**
  - 검사: "벌금을 세 번 받고도 또 그랬느냐" 등 날카롭지만 **정당한** 추궁
    - 끝까지 들으면 최후진술이 진심이 되고 **진지한 반성** 카드가 생긴다
    - 끊으면 최후진술이 형식적이 되어 카드가 없고, 정당한 신문 제지로 지적(판결 영향 off: 반성은 일반인자라서) `[내 판단]`
  - 변호인: 생활 사정 확인(생계형 보강). 재판장 보충신문: 명확화 1개
- **고증 메모**: 절도는 반의사불벌죄가 아니므로 처벌불원은 양형인자일 뿐이고 판결 시점 의사를 본다. 반의사불벌죄의 철회·재표시 제한은 후속 회차에서 따로 확인 `[확인필요]`
- **양형 요소 (절도 양형기준 원문, 2025. 7. 1. 기준)**
  - 유형: 일반재산 절도 2유형 "일반절도" — 감경 4월~10월 / 기본 6월~1년6월 / 가중 10월~2년
  - 특별감경 후보: 생계형 범죄(행위), 처벌불원 또는 실질적 피해 회복(행위자, 절도에서 행위인자와 동등 평가 가능)
  - 일반감경 후보: 진지한 반성
  - 일반가중 후보: 누범 아닌 동종 전과(집행 종료 후 10년 미만)
  - 집유 주요긍정: 생계형 범죄, 처벌불원·실질적 피해 회복 / 주요부정: 동종 전과(5년 이내 3회 이상 벌금) / 일반긍정: 피해 경미, 진지한 반성 / 일반부정: (없음)
  - **카드 출처**: 생계형 ← 피고인 의견서·피고인신문(항상 확보) / 처벌불원 ← 처벌불원서 + 점주 증언(태도 변화) / 진지한 반성 ← 최후진술(태도 변화) / 피해 경미 ← 피해품 목록 / 동종 전과 ← 수사보고
    - 구현 메모: 증거 하나에 카드 하나라서 피해품 목록·영수증 증거는 영수증 카드를 주고, **피해 경미**(`c_minor`)는 주신문에서 영수증을 제시하고 점주가 피해액을 확인하는 답변에서 생긴다. 1화 결과 화면의 참여관 한 줄은 시나리오 데이터에 라인 자리가 없으므로 UI가 `outcome.hypothetical`로 그린다
  - **경로별 권고** (엔진이 계산, 아래는 기대값)
    | 경로 | 특별인자 | 권고영역·범위 | 집유 |
    |---|---|---|---|
    | 정석(처벌불원 유지) | 감경 2 (생계형, 처벌불원) | 감경, 특별 조정으로 하한 1/2 → 2월~10월 | 주요 긍정 2 대 부정 1 → 종합 판단 |
    | 처벌불원 상실·철회 | 감경 1 (생계형) | 감경 4월~10월 | 긍정 1 대 부정 1 → 종합 판단 |
  - 어느 경로든 집유는 종합 판단이 되어 플레이어가 처음으로 "재량"을 쓴다. 차이는 형량 범위와 반성·피해 회복 같은 일반 사유의 개수다
- **구형**: 징역 1년 → 6월 미만 선고 시 검사 항소(항소심에서 대부분 기각되어 "항소 기각"을 경험)
- **형종**: 1화는 징역(집행유예 여부 포함)만 다룬다. 절도는 벌금형도 가능하므로 벌금 선택지는 후속 과제 `[내 판단, 고증상 빈 곳]`
- **숨겨진 진실**: 작가 설정만 두고 공개하지 않는다(synopsis). 내용은 시나리오 단계에서 정함

## 7. 데이터 스키마 (요지)
`gameplay.md`의 "시나리오 데이터에 필요한 것"을 기준으로 한다.
- `meta`: id, 제목, 재판부(단독/합의), 선입견 유형(none), 진실(비공개 메모)
- `documents`: 공소장, 피고인 의견서 (공판 전 열람)
- `opening`: 피고인 의견(칸별), 쟁점 칸 정의
- `evidence[]`: id, 표목, 제출자, 동의 여부, 잠금, 해금 조건, 본문, 카드 정보(구성요건 칸 연결 가능 여부, 자백 여부)
- `witnesses[]` / `defendantExamination`: 신문 단계별 대사 라인. 라인마다 화자, 제지 가능 여부, 정당/부당 구분, 제지 시 사라지는 라인/카드, 판결 영향 플래그
- **조건·플래그 (태도 변화)**: 라인·카드·항소심 판단마다 `when`(등장 조건: 플래그 조합)과 `sets`(남기는 플래그). 제지·방치·이의 결정·보충신문 선택이 플래그를 남긴다. 조건식은 플래그 AND/NOT 정도로 단순하게 유지
- `boardAppealView`: 칸별 항소심 판단(증명됨/의심 남음, 근거 증거, `when` 가능)
- `objections[]`: 발생 라인, 올바른 결정, 판결 영향
- `supplementaryQuestions[]`: 칸, 유형(명확화/입증 대행/선입견), 답변, 생성 카드
- `closing`: 구형, 최종변론, 최후진술
- `sentencing`: 양형기준 유형표, 인자 정의(특별/일반, 행위/행위자, 방향, 무게), 집유 참작사유, 회차별 인자 존재 조건(어떤 카드가 있어야 체크 가능한지)
- `appeal`: 피고인 항소 규칙(1화: 실형이면 항소)
- 런타임 검증: 로드 때 스키마 검증 실패 시 개발 화면에 오류 표시
