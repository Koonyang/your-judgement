# 대사 검수 (dialogue-review)

대상: `data/scenarios/<ep>.json`의 모든 `speaker`+`text` 줄, 보충신문 질문(`text`+`answer`), 또는 사용자가 준 대사 초안.
목표: **읽기 매끄럽고, 사람 냄새 나고, 분량이 충분하고, 법정 고증에 맞고, 게임 장치와 어긋나지 않는 대사.**

## 0. 먼저 읽을 것
- `docs/story/storyline.md` §0(볼륨 목표), §3(인물표), 해당 회차 절
- `docs/design/gameplay.md`의 제지·이의·보충신문 규칙 (필요한 부분만)
- 1화 기준선: 대사 약 50줄·한글 약 1,250자(읽기 약 4분). 이게 "너무 적다"는 출발점이다

## 1. 기계 점검 (항상 먼저)
```bash
node .claude/skills/dialogue-review/scripts/dialogue-stats.mjs data/scenarios/<ep>.json --script
```
줄 수·글자 수·화자별 비중·구간별 분량, 대사 상자 초과(공백 제외 90자), 증인·피고인 단답, id 중복(엔진 `heard`가 id로 줄을 찾으므로 중복은 버그), 역전재판식 외침, 느낌표 남용을 뽑는다. 숫자는 그대로 보고에 쓴다.

## 2. 읽기 점검 (대본을 처음부터 소리 내 읽듯이)
다섯 축으로 본다. 각 지적에는 **줄 id**를 단다.

### A. 흐름
- 질문과 답이 실제로 맞물리는가. 답이 질문보다 앞서 가거나(묻지 않은 정보를 먼저 말함) 질문을 그대로 되풀이하지 않는가
- 다음 사람으로 넘어가는 이음매(“이상입니다” → “변호인, 반대신문하십시오”)가 빠지거나 덜컥거리지 않는가
- 정보 덤프: 한 줄에 사실 두 개 이상을 몰아넣었으면 나눈다
- 같은 문형 반복(“~지요?” “네.” “~지요?” “네.”)이 세 번 이상 이어지면 리듬이 죽는다
- 장면 전환(기일 시작·휴정·선고)에 참여관이나 재판장의 한 줄 안내가 있는가

### B. 볼륨과 밀도
- 목표: 회차당 1화의 2~3배, **정보 대사 : 캐릭터 대사 ≈ 1 : 1**
- 캐릭터 대사의 예: 머뭇거림, 기억을 더듬는 말, 질문에서 살짝 비껴간 하소연, 말버릇, 방청석 반응, 기일 전후 참여관·배석과의 대화
- 단답(8자 이하)이 증인·피고인 대사의 20%를 넘으면 표시. 단, 긴장 장면에서 일부러 쓴 단답은 살린다
- 캐릭터 대사 안에 단서를 숨기는 것이 이 게임의 볼륨 원칙이다(제지하면 사라지는 정보). 순수 잡담만 늘리지 않는다

### C. 인물 말투
- `storyline.md` 인물표와 대조. 인물마다 **말투 3요소**(어휘 수준, 문장 길이, 버릇)를 한 줄로 정리하고 어긋난 줄을 짚는다
- 증인·피고인은 법률가처럼 정확하게 말하지 않는다. 날짜·금액을 처음부터 완벽히 말하면 부자연스럽다(기록을 보고 확인하는 흐름이 낫다)
- 검사·변호인은 법정 경어체. 개성은 어휘와 리듬으로만 낸다
- 재판장 말은 짧고 중립. 감정 표현·예단·훈계 금지(양형 이유 설명·최후진술 뒤 한마디 같은 정해진 자리 제외)

### D. 법정 고증
- 역전재판식 구두 언쟁·외침 금지. 이의는 “이의 있습니다. 유도신문입니다.” 수준의 짧은 신청과 재판장의 결정
- 절차 문구: 진술거부권 고지(형소법 §283의2), 인정신문(§284), 증인 선서(§157·§158), 증언거부권 고지(§160) 등은 실제 문구에 가깝게 `[확인필요]`
- 주신문에서 유도신문 금지, 반대신문에서는 허용(형소규칙 §75·§76 `[확인필요]`). 위압적·모욕적 신문 금지(형소규칙 §74② `[확인필요]`)
- 판사는 현출된 증거만 안다. 대사가 공소장일본주의·부동의 잠금을 깨고 판사가 볼 수 없는 정보를 흘리면 지적
- 법률 용어는 정확히, 그러나 증인 입에서는 일상어로(“집행유예” 대신 “감옥 안 가는 거”)
- 새로 생긴 법리 주장은 `storyline.md` §8 고증 장부에 항목을 추가하도록 제안한다

### E. 게임 장치 정합
- `interrupt`(제지 지점): 끊겼을 때 `resumeAt` 줄로 바로 이어 읽어도 말이 되는가. 정당한 신문(`legit: true`)은 정말 끊고 싶게 거슬리면서도 정당한가
- `objection`: 이의 대상 질문이 실제로 이의 사유(유도·여죄·의견 요구 등)에 해당하는가. 인용 시 `onSustain.resumeAt` 이음매가 자연스러운가
- `yieldsCards`: 카드를 주는 줄이 그 카드 내용을 실제로 말하는가. 카드 제목과 대사의 사실이 일치하는가
- 보충신문 질문(`kind`: clarify·burden·bias 등)은 그 성격에 맞는 말투인가. 선입견 질문은 플레이어가 유혹을 느끼되 선을 넘는다는 걸 알아챌 수 있어야 한다
- 복선(`storyline.md` §4)이 이 회차에 심겨야 하면 해당 대사가 있는지, 너무 티 나지 않는지 본다

## 3. 보고 형식
채팅으로 보고한다(사용자가 파일을 원하면 `docs/reviews/dialogue-<ep>.md`).
1. **숫자 요약**: 스크립트 결과에서 줄 수, 글자 수, 읽기 시간, 목표 대비 배수
2. **지적 목록**: 심각한 것부터. `[축] 줄id — 문제 — 고친 대사` 형식. 고친 대사는 JSON에 바로 넣을 수 있게 화자·문장으로 쓴다
3. **늘릴 자리**: 볼륨이 부족하면 어느 줄 사이에 몇 줄을 어떤 내용(캐릭터 대사 + 숨긴 단서)으로 넣을지 구체적으로. 새 줄 id는 기존 규칙(`owner_3a` 식)을 따르고 중복되지 않게
4. **고증 메모**: 새로 생긴 `[확인필요]`

## 4. 하지 않는 것
- 사용자가 "고쳐"라고 하기 전에는 시나리오 JSON을 고치지 않는다. 검수는 제안까지
- 정보 대사를 빼서 볼륨을 맞추지 않는다. 줄이기보다 사이를 채운다
- 플레이어가 판사보다 많이 알게 만드는 대사를 넣지 않는다(시놉시스의 예외 회차 제외)
- 젠더 갈등 소지가 있는 표현, 실존 인물·사건을 떠올리게 하는 고유명사를 쓰지 않는다
